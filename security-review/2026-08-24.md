# Security Audit — go-ojol backend

**Date:** 2026-08-24  
**Scope:** `backend/auth`, `backend/trip`, `backend/gateway`  
**Type:** Static code review (not penetration test)

## Summary

Auth foundations are solid (bcrypt, ES256 JWT, refresh rotation, Casbin RBAC, session revocation on auth service). Main gaps: **trip service trusts JWT until expiry without session checks**, **secrets in committed seed data**, and **missing hardening** (rate limits, security headers, production Gin mode).

| Severity | Count |
|----------|-------|
| Critical | 0 |
| High     | 2 |
| Medium   | 7 |
| Low      | 5 |

## Findings

### High

#### H1 — Revoked sessions still valid on trip service
**Files:** `trip/middlewares/authentication.go`, `trip/pkg/jwks/verifier.go`

Auth middleware validates JWT + active session in DB. Trip only verifies JWT signature via JWKS. After logout/revoke, access tokens remain usable on trip endpoints until expiry (~15 min).

**Fix:** Validate `session_id` claim against auth DB or shared session store; or use short-lived tokens + introspection endpoint.

---

#### H2 — Plaintext passwords in committed seed data @Intentional:"It's just my dummy development data"
**File:** `auth/database/seeders/json/users.json:4,10,17`

Known passwords (`hehe1234`) for admin/customer/driver accounts are tracked in git. Risk if seeds run in staging/production or credentials are reused.

**Fix:** Use env-based seed passwords or one-time generated secrets; rotate seeded accounts after deploy.

---

### Medium

#### M1 — JWT accepted via query string
**File:** `trip/middlewares/authentication.go:48-52`

`?token=` fallback for WebSocket auth. Tokens can leak via access logs, proxies, browser history, and Referer headers.

**Fix:** Use `Sec-WebSocket-Protocol` or post-connect auth; avoid query-string tokens.

---

#### M2 — WebSocket allows missing Origin @question:"The client is mobile app, does it still matter ?"
**File:** `trip/modules/dispatchws/controller/dispatchws_controller.go:52-54`

`checkOrigin` returns `true` when `Origin` header is empty, bypassing CORS intent for non-browser clients (acceptable) but also allows origin-less cross-context connections if misconfigured.

**Fix:** Require Origin in production; reject empty origin unless explicitly needed.

---

#### M3 — No rate limiting on auth endpoints @request:"Throttle the endpoint after 4 times of failed creds"
**Files:** `auth/modules/auth/routes.go:24-26`

`/register`, `/login`, `/refresh` have no throttling → brute-force and credential-stuffing risk.

**Fix:** Add per-IP/email rate limits (Redis or middleware).

---

#### M4 — Internal errors returned to clients @request:"Defined global 500 error message like 'An error occured on our server'"
**Files:** All controllers (e.g. `auth/modules/auth/controller/auth_controller.go:67,96`)

`err.Error()` from DB/service layer is echoed in API responses → schema/table names and stack-adjacent details may leak.

**Fix:** Map errors to stable client messages; log internals server-side only.

---

#### M5 — Missing security headers @question:"Look at M2 @question"
**Files:** `auth/cmd/main.go`, `trip/cmd/main.go`, `gateway/cmd/main.go`

No CSP, `Strict-Transport-Security`, `X-Frame-Options`, or `X-Content-Type-Options`.

**Fix:** Add security-headers middleware at gateway.

---

#### M6 — Gin debug mode not enforced for production
**Files:** `auth/cmd/main.go:57`, `trip/cmd/main.go:58`, `gateway/cmd/main.go:61`

Services use `gin.Default()` without setting `GIN_MODE=release`. Debug mode can expose verbose errors.

**Fix:** Set release mode when `APP_ENV != localhost`.

---

#### M7 — Admin delete route ignores `:id` param
**File:** `auth/modules/user/controller/user_controller.go:100-102`

`DELETE /user/:id` requires admin role but deletes the **authenticated** user, not the path ID. Admin self-delete only; intended admin action may not work.

**Fix:** Use `ctx.Param("id")` with ownership/admin checks.

---

### Low

#### L1 — User entity exposes `password` JSON tag
**File:** `auth/database/entities/user_entity.go:12`

`json:"password"` on GORM model. Safe today (list query uses separate struct), but risky if entity is ever serialized directly.

**Fix:** Use `json:"-"` on password field.

---

#### L2 — Profile uploads are public-read
**File:** `auth/pkg/uploadthing/client.go:157`

Upload ACL `public-read`. Profile pictures are world-readable by URL.

**Fix:** Confirm intent; use private ACL + signed URLs if PII-sensitive.

---

#### L3 — Upload MIME type trusted from client header
**File:** `auth/modules/auth/service/auth_service.go:237-246`

Content-Type from multipart header is validated, not file magic bytes → extension spoofing possible.

**Fix:** Sniff first bytes (`http.DetectContentType` or `filetype`).

---

#### L4 — Root `.gitignore` is empty
**File:** `/.gitignore`

Repo root has no ignore rules; relies on per-service `.gitignore`. Easier to accidentally commit secrets at monorepo root.

**Fix:** Add `.env`, `*.pem`, `keys/`, logs at root.

---

#### L5 — Go stdlib CVEs (govulncheck)
**Affected:** `net/url`, `crypto/tls`, `net/http`, `encoding/xml` @ go1.26.4  
**Fixed in:** go1.26.6

**Fix:** Upgrade Go toolchain and rebuild.

---

## Positive Controls

- bcrypt password hashing (`auth/pkg/helpers/password.go`)
- ES256 JWT with JWKS endpoint; trip verifies issuer + kid
- Refresh token rotation + SHA-256 hash at rest
- Session revocation on auth service (`auth/middlewares/authentication.go:80-84`)
- Casbin RBAC on protected routes
- CORS allowlist (not `*`); credentials only when origin matches
- JWT private key gitignored (`auth/.gitignore`); env-driven key path
- GORM parameterized queries; no string-concat SQL in app code
- No hardcoded API keys/tokens in source (env vars used)

---

## Recommended Next Steps

1. Add session validation to trip service (highest impact).
2. Remove/rotate seeded credentials; never deploy default passwords.
3. Harden gateway: security headers, rate limits, `GIN_MODE=release`.
4. Upgrade Go to 1.26.6+.
5. Run `govulncheck ./...` and `trivy` in CI.
